# AI Use Cases — the draft, in pencil

The client's RFP wants a tool that answers plain-language questions. This
file is where your team decides what that AI helper will actually do —
BEFORE anyone builds it. Next week's classes (T8A: what AI is good and bad
at, T8B: how AI earns a place in a product) grade this draft. Expect to cut
at least one line. That's the point of pencil.

## The shape

Every use case is ONE sentence:

> "A user asks the AI **___**, and it answers **___** using **___** data."

Example (steal the shape, not the words):

> "A project manager asks the AI *'where is ticket INC0012345?'*, and it
> answers with the ticket's state, team, and latest activity, using the
> incident table through `/tickets`."

## The honesty rule

If your API can't fetch the data a use case needs, the AI can't answer it.
Every use case must name the endpoint (or query) that would feed it. No
endpoint, no use case — or better: write the missing endpoint first.
