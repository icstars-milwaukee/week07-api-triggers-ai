My API won't start

Three usual causes, in order:

1. You're in the wrong folder. The command runs from your project's folder, where data/ and node_modules/ live — not from the lesson repo.

2. Dependencies missing. Run npm.cmd install first — the .cmd matters on Windows.

3. Node too old. The starter needs Node 24 or newer. Check with node --version.

It says a port is already in use

You already have a server running from an earlier attempt. Find that terminal and press Ctrl+C, then start it again. One API at a time on port 8000.

An endpoint returns an error instead of data

Good — read it. These starters explain themselves when you ask badly: /tickets with no team comes back with {"error": "Say which team: /tickets?team=NAME"}.

That's not a crash, it's the API telling you how to ask. Breaking it on purpose is part of the job — and rewriting that message for your own users is part of the deliverable.

What is TypeScript, actually?

JavaScript, with the types written down. It is not a new language — delete every : something and you have JavaScript back.

The notes are for a checker that reads your code before it runs, so a misspelled field is caught in your editor instead of by the client.

The seven things you'll meet in the starter: : string ("is a") · type ("name a shape") · Row[] ("a list of") · Record<string, number> ("keys I don't know yet") · ? and ?? ("might be missing" / "use this instead") · as Row[] ("trust me") · and type inside an import.

Slides 6–11 of the workshop deck walk through all of it, with two live playgrounds.
